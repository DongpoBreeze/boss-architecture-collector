# 桌面工作流与关键契约

本文描述当前生效行为，不保留逐轮开发记录。入门见 [README](../README.md)，CLI 兼容行为见[命令行参考](command-line.md)，代码地图与验证说明见[开发文档](development.md)。桌面工作台只显示阶段操作提示，不提供静态 AI 判断规则的第二份展示；本任务实际保存的 AI 规则通过“修改复核规则”查看与编辑。

## 页面与采集方案

- 默认桌面入口是同窗三个模块的 Tk GUI：“01 岗位采集”“02 后处理审核”“03 投递数据导出”，初始进入后处理。后处理只展示四步，AI 名单确认后进入导出页预览并导出 JSON。旧混合工作台只通过 `desktop_app.py --legacy-workbench` 显式打开。
- 构造、切页、刷新、打开任务、主题切换、导出预览或采集完成均不隐式执行阶段或请求外部服务。采集、登录准备、审核和导出共享执行互斥，查看导航不受阻；F5 只刷新当前页。
- 采集页只运行列表采集。手动“用此数据新建后处理任务”仅填表，已有任务需确认离开，不自动创建、运行或确认；三个模块各自保留状态，共享日夜主题。
- 默认配置为 6 城（上海、深圳、杭州、广州、成都、北京）、2 档薪资、本科；`current`（当前求职）11 词 × 4 个经验段共 528 组，`target`（成长参考）6 词 × 2 个经验段共 144 组。全量 672 组，每城 112 组。检索分组不是“重点投递 / 海投池 / 暂不投”。
- 一个组合包含城市、关键词、薪资、经验、学历。维度与逐组选择先于城市 / 分组 / 数量限制；数量上限按预览顺序取所选前 N 组，不是新增 N 组。规划数量与已落盘采集进度分开显示。
- 01 “采集浏览器”默认 Chrome + Edge 并行采集，可显式选择仅 Chrome；使用独立 CDP 端口 9222 / 9223 与 profile，共享同一个采集输出根。“每浏览器采集并发”默认 3，范围 1–8，每槽是独立 CDP 页面与采集进程。在当前城市、检索分组、勾选与上限形成固定执行集合后，按配置顺序奇偶分给浏览器，再在每侧分给并发槽；组合无重叠，并集等于执行集合，空槽不启动。状态汇总、各槽详情与来源日志独立展示，清单在文件锁内合并，不能用单槽分片覆盖完整预计组合。
- 列表翻页等待可设置最短 / 最长秒数，默认 12–22 秒，接受有限小数，要求 `0 ≤ 最短 ≤ 最长 ≤ 300`；相同值表示固定等待。设置只影响列表页之间的间隔，首屏、滚动、登录检查和超时等待继续沿用上游行为。范围与并发在启动前冻结并验证，运行中禁改；切页保留本页设置，修改后下次启动生效。
- 采集页准备登录在后台每浏览器只准备一次，双模式下显式准备仍会准备两侧；多槽复用该侧端口与登录态，每槽只操作自己的页面。一侧出现验证后，同侧在组合边界停止继续调度，另一浏览器继续；普通失败按槽保留并等待续采。Chrome / Edge 各有“人工完成，继续”按钮，只发给该侧当前真正等待的采集器，不能向正常采集槽发送回车。暂停、停止和关窗作用于本次拥有的所有采集进程树，待它们结束再释放页面执行状态；各自保存中断组合，续采跳过已完成组合。切页与只读预览不触发浏览器或采集。
- 多槽安全验证暂停标记只属于本次会话的单个浏览器，人工继续不删除标记；当前等待组合可以重试，完成后停在组合边界，不自动启动更多搜索。剩余组合在当前会话结束后通过再次“开始 / 续采”读取检查点补齐，使用新的会话标记。普通 CLI 未启用 GUI 会话协议时不读取这些标记。
- 编辑器支持既有城市、薪资、经验条件选择及两组关键词编辑；本科固定。取消不保存，应用另存唯一新方案。catalog 保留旧身份，新词按内容生成稳定 ID，不得复用旧 ID 改变查询含义。
- 打开、预览、勾选、登录准备不写采集源；GUI 登录准备使用临时根。显式采集时把完整实际方案保存到源根 `collection-plans/*.json` 并作为 CLI `--config`。同组合 ID 的已知检索语义冲突应阻断续写。
- 新建后处理任务时只读合并源内方案的 catalog，必要时在源外另建不可变来源识别配置并绑定任务；不以未来检索勾选过滤已存在 raw。损坏方案或同 ID 映射冲突明确报错，不静默漏读。源文件、旧任务和旧报告不变。

## 固定源、运行与确认

创建任务绑定完整采集根（读取 `raw/current`、`raw/target`），固定任务名、城市、轨道、数量及配置。数量默认不限，自定义正整数按实际去重岗位数封顶；GUI 导入使用稳定组合顺序的 `balanced-dedup` 均衡抽样。旧任务改范围或数量通过新建任务完成，不直接改其 manifest。

任务范围、原始文件安全清单及 `size / mtime_ns` 固定；配置单独保存 SHA-256。导入前后核对固定源，不例行哈希全部 raw。对绑定源补采后应新建任务，不把旧确认结果当成新数据审核结果。不按日期搜寻或自动合并其他运行。

默认桌面审核固定为 `import → shortlist → fetch-jd → llm`，之后由独立投递页导出。底层任务清单仍保留 `report` 第五键，以兼容旧任务和显式报告 CLI；默认桌面不运行、不重算报告，不迁移历史结果。

- 每一步必须手动运行，完成后停住，等待审核与确认。导入也不例外。`confirm` 仅冻结名单和下一步输入，不调用执行器。
- 后续步骤只能使用上一有效已确认名单。岗位 ID 唯一；每步结果集合必须与固定输入一致，不得静默增删岗位。
- 四步均支持搜索、分页、剔除、恢复和“采用建议”。剔除只影响本任务，不删原始数据。人工保留 / 剔除重跑和重新打开任务时保持；“采用建议”才清空人工覆盖。AI 阶段允许对待核实岗位人工保留或剔除，导出以最终确认的保留名单为准，原始 AI 判断、理由及技术状态仍保留追溯。
- 列表初筛与 AI 复核中，建议保留沿用原来的默认文字和行底色，不额外染绿；建议剔除显示红色字与浅红 / 深红行底，随日夜主题切换。列表初筛的建议色与人工勾选独立；AI 复核有显式人工决定时，行色与人工名单一致：人工保留使用中性色，人工剔除使用剔除色，原始 AI 建议仍在详情中显示。AI 待核实项使用待核实色，人工处理后及时更新颜色与数量。输入预览、导入、JD 补抓及报告不沿用建议色，失效旧结果优先显示黄色提示。
- 回改确认名单或重跑上游，会取消下游确认并将已执行下游标为 `stale`。旧版本保留追溯，但失效结果不能编辑、确认或授权新导出；需重跑并确认受影响步骤。已生成的导出保留原快照，不自动更新。
- 只有有效 `completed` 可以确认；`pending/running/paused/stopped/waiting/failed/stale` 不能确认。暂停、安全验证和失败不能冒充完成。打开历史任务仅恢复状态，运行锁阻止同任务重复执行；异常退出且无活跃执行者时可恢复为暂停。JD 补抓使用双浏览器时依然遵守该状态规则：一侧暂停不会丢弃另一侧已落盘的结果，续跑只重试未完成条目。
- 空名单是合法审核结果，GUI 明确提示后可确认。后续空 JD / AI 只生成本地空检查点，不启动浏览器、不读取模型配置或请求服务；空导出仍遵守确认与 schema 契约。

确认和名单编辑均可携带已审核的阶段快照，在同一文件锁内核对结果、输入、人工选择和确认版本。GUI 确认必须传入所见快照；另一窗口改变名单后拒绝旧确认并刷新，不静默冻结用户尚未看过的新名单。执行完成或中断的状态提交会有界等待短暂锁竞争；异常收尾须先确认本次自有子进程已经退出，才释放本次运行租约。

### 本阶段重置与断点继续

四个审核阶段均提供独立的“重置本阶段”按钮；本步尚未运行、前置未确认、同任务已有运行、宿主其他执行中或窗口关闭中禁用。普通“运行 / 继续本步 / 复用检查点运行”沿用正常阶段执行语义；“重置本阶段”经确认后只清空当前阶段进度、结果、检查点与阶段状态，不会立即运行执行器。取消确认不更改任务或文件；重置完成后仍须单独点击“运行本步”才重新执行。

- 重置后的单独运行按阶段执行：导入重新读取绑定的固定源并去重，源改变须新建任务；列表初筛重算当前确认输入的建议；JD 重抓当前确认输入的全部正文，完整 JD 也重抓；AI 复核重新请求全部合格完整 JD，绕过此前成功缓存，可能产生用量。
- 重置仅清理所选阶段，并取消下游确认、将已执行下游标记为 `stale`；不改上游结果与确认。需查看的当前阶段旧结果应在重置前查看；失效下游文件不会被当作最新结果打开。
- 重置本身不会访问浏览器、读取模型配置、产生模型用量或调用任何阶段执行器。重置通过任务接口执行，由工作线程完成并刷新界面；失败时界面不会显示为已成功重置。正常运行 / 暂停 / 继续仍由执行器管理断点和检查点。

## 筛选、JD 与 AI 复核

### 列表初筛

标题 / 技能按有限关键词、同义表达和中英文规则宽召回 AI / 应用 / 产品 / 系统架构、产品助理、方案、FDE、Agent / RAG / Workflow、系统集成、实施交付、技术型客户成功、知识管理、AI 落地赋能及相关过渡方向；不是向量检索或模型语义判定。新增方向仍检查真实工作对象，不能因“架构”放行芯片 / 整车 / 云底层全部岗位。

列表保存互斥的 `list_queue` 与 `list_queue_reason`：

- `relevant`（明确相关）：有较强方向标题或应用 / 方案证据；强 AI 架构、AI 产品、FDE 标题缺少技能标签时仍可进入，但职责与要求待 JD 核实。
- `verify`（待核实）：泛架构 / 产品项目、系统集成等过渡线索，或行业对象、算法 / 基础设施、销售技术占比存在歧义；不是认定胜任。
- `excluded`（剔除）：明确排除或标题 / 技能没有目标方向线索，保留原文原因。

`list_pass=true` 包含前两类，默认均建议保留；`score` 只排序，不设“至少 5 分”的门槛。`list_priority` 兼容保留，并与三队列一致。没有 JD 时不把列表命中当作六项职责证据。

- 明确月薪上限 **<17K** 直接建议剔除；上限 =17K、跨 17K、面议、缺失、非月薪或无法确定上限不因该门槛排除，保留核实标记。不把额外薪月、年终奖平均成固定月薪。薪资原文与 `list_salary_below_target` 证据保留。
- 纯开发须有明确开发 / 研发编码标题（含裸 Java / Python 等常见开发头衔），且缺乏方案、总体架构、产品、业务 / 系统集成、实施交付或 PoC 的混合职责证据。仅 AI、Agent、RAG、语言、框架或“架构设计经验”能力标签不能豁免；方案岗位会编程不因此剔除，信息不足不猜测纯开发。
- 纯获客销售、明确纯算法 / 底模、纯底层基础设施、硬件工艺及明显无关方向排除，但不按单个“销售、算法、运营、培训、K8S、资深、校招”等词一票否决。技术销售、售前、FDE 要核对本人承担的技术职责；仅介绍 / 售卖 Agent 产品不是本人技术交付证据。
- “无需 / 不负责 / 不涉及”和明确由其他团队承担的职责按子句排除，不能用其中的 PoC / 交付词刷命中。裸 AI、PS/AE/AI、AI Coding、Python / Java 本身不证明应用对象或方案交付职责。经验偏高先标注，不在列表步按一个标签全部排除。

同一岗位的标题、薪资、技能和标签保存 `field_candidates` 候选及轻量来源引用，`field_conflicts` 标记冲突，完整来源仍在 `observed_in`。展示值按稳定顺序选择，不声明某来源更新或更可信；初筛检查全部候选，冲突加入核实依据。薪资硬排除要求所有候选均可解析为明确月薪上限且全部 **<17K**；任何未知、开放上限或跨线候选都不能据此硬排除。其他来源中的正向词不抹去独立明确的职责排除证据；这些列表规则不用于推翻有效新版 AI 判断。

队列筛选不改变名单；显式“仅保留明确相关”替换整步选择（相关全保留、其余移出），“加入待核实”恢复完整待核队列、其他队列取舍不变。操作前提示全量范围，后台在单个存储事务中校验已审核快照并提交；并发修改则拒绝，不覆盖另一窗口决定。仍需人工确认，不能自动补抓 JD。

CLI 与桌面均保留合并建议 `jd_input.json`，另输出 `jd_relevant.json / jd_verify.json`；索引、manifest 与报告保存 `list_queue_counts`（含零值）及初筛版本。建议文件不代替任务实际确认名单。界面按落盘队列显示，不重跑筛选器。

历史缺少有效队列字段的结果，仅按旧 `list_pass / list_priority` 做带“旧版兼容”标记的保守展示；整步含旧字段时禁用两种队列快捷动作，提示手动重跑初筛，原有逐岗取舍与采用建议保留。旧任务不自动重写，重跑保留人工选择。

列表初筛仍独立执行上述门槛；新版 `simple-v1` AI 与报告不再重算关键词、职责证据或六维来推翻 AI 判断。`excluded_terms` 仅是历史风险词记录，不等于自动排除。不新增经验 / 学历 / 年龄硬排。

### JD 补抓

只抓上一确认名单的正文，人工恢复的 `list_pass=false` 岗位也必须包含。输出保留全部输入，`recommended_keep=true`、`jd_analysis_status=not_run`；不作职责关键词筛选、不生成三层分类，也不继承旧语义判断。人工仍可审核取舍。

JD 页面并发 `jd_workers` 默认 3，范围 1–32；每页固定滚动 3 次，使用独立页面 / CDP 连接并复用专用 Chrome 登录态。本项目 `jd_parallel.py` 适配上游，不修改上游安装。实际同时页面数不超过并发与本批待抓数的较小值；GUI 批大小默认 30，独立于 JD / AI 两类并发。

桌面 JD 页直接显示浏览器模式、准备 / 登录按钮与 Chrome / Edge 状态，不必展开执行设置。新偏好默认 `dual`；显式保存的 `single` 仍可选择，切换立即保存且运行时原样透传，执行中不能热切换。CLI 兼容保留单 Chrome 默认，可将 `browser_mode` 设为 `dual`，使用独立的 Chrome / Edge CDP 端口（默认 9222 / 9223）和 profile。每侧各最多 `jd_workers` 个页面，例如设为 2 时双侧总计最多 4 页。每批待抓输入按稳定顺序连续切分，Chrome 取前 `ceil(N/2)`，Edge 取余下；该批仅剩 1 岗时只需 Chrome 执行。两侧检查点在合并前分别保存，合并输出按原输入顺序且 `job_id` 唯一。一侧遇到验证只暂停该侧，另一侧继续保留已完成记录；续跑跳过 `success`，只重试未完成记录。

完整度统一由 `process_architecture.detail_completeness` 判定：无正文为 `missing`；明确部分、失败、截断标记的非空正文为 `partial`；其他非空旧记录兼容 `complete`。缓存先比完整度再比长度，较短完整正文优于长截断正文；续跑跳过完整 JD，补抓 partial。

恢复时在重分片或覆盖文件前，先汇总合并检查点与 Chrome / Edge 两侧检查点，按岗位 ID 和完整度选优并持久化；进程在侧文件已写、合并文件未写时退出，也可保住完整正文。各侧预检状态传入调度，未准备好的一侧保存暂停结果且不导航详情。持久化失败会先向两侧广播停止，再有界收尾，保留已经成功写入的检查点。

完整度与验证状态分开统计，可能重叠，不能直接相加。即便已有正文，涉及当前输入的登录 / 安全验证仍使步骤 `waiting`，不可确认；部分正文不能冒充完整 JD 送入模型。当前确认输入和批大小决定有效批次，缩窄范围或重分批时清理旧分组状态，不让旧 gate 永久阻塞；当前真实验证仍必须暂停。

### AI 语义复核

仅确认名单中的完整 JD 进入模型，每个岗位独立请求。目标为企业 AI 解决方案架构师 / AI 应用架构师、AI 产品经理（应用 / Agent / 知识库），以及可积累业务需求分析、方案设计、系统集成、PoC、交付与迭代经验的相关岗位，不强求同名。排除主业代码开发、算法研究 / 模型训练、硬件、纯销售 / 渠道招商、底层基础设施；产品、方案岗位仅需懂技术或配合开发不能被误判为纯开发。

模型严格只返回两个键：`判断`（符合 / 不符合 / 信息不足）、`理由`（一两句话）。不要求输出岗位 ID、正文依据、六维、置信度或能力差距；ID、状态、模型及缓存元数据由本地追加，记录标记 `review_format="simple-v1"`。JSON / schema / 岗位身份与签名技术校验仍有效。符合建议保留、不符合建议剔除；信息不足、缺失 / 部分正文、配置失败、请求失败、缺失或无效缓存默认进入独立 `pending_ids` 待核实集合。阶段结果有效且未运行时，用户可逐条或批量人工保留 / 剔除；人工决定优先，未处理条目仍待核实。人工处理不改写或伪装 AI 成功，不补发模型请求；“采用建议”清除人工决定并恢复默认三类。保留、剔除、待核实始终互斥且覆盖本步全部结果，界面数量随人工操作同步更新。

运行期间自动轮询已落盘的 AI 检查点，三类名单、统计与当前页来自同一份后台快照；无需切步骤或按 F5。文件未变化时复用正文、投影和搜索索引；新增或改变单岗结果只更新必要的投影与搜索文本。筛选在后台执行，Tk 主线程仅更新当前页有差异的行，并保留选择、焦点和滚动位置；带序号的后台视图防止较旧刷新覆盖较新结果。暂停、完成或切换任务后重新以有效阶段数据展示。

模型接收完整职位职责正文及任职要求，支持“职位职责 / 岗位职责 / 工作内容”等段落标题。发送前不按通用关键词或固定动作词表删去职责句；公司介绍、福利、职位名称、技能与检索标签不充当职责。AI 直接按实际工作对象、动作和上下文理解，不强求同名或固定词命中。新结果界面展示判断和理由、必要的运行元数据、技术错误、人工选择与来源；技术失败不包装成模型理由。

AI 页唯一的规则查看 / 编辑入口为“修改复核规则”，编辑器直接载入当前任务保存的文本，支持滚动、撤销、保存本任务规则、恢复默认草稿和取消；“恢复默认”须保存后才生效，固定两字段输出协议由程序补充。保存不会热切换已发出的请求；重置 AI 阶段本身不修改规则，也不会发起请求。AI 阶段重置后，只有随后显式点击“运行本步”时才读取已保存规则并开始模型处理；若识别到旧六维 / `target_relevance` / `experience_assessment` 结构的自定义规则，此时切换为简化默认，其他自定义规则保持。旧 rich 结果在重置前显示“只读历史，需重跑”，不能冒充新版成功；应在重置前查看需要保留的旧结果。

规则保存到本任务，不修改项目默认提示词、其他任务或原始数据。运行中不能编辑；相同规则保存不作重复失效处理。规则改变会取消 AI 与兼容报告确认，并将已执行结果标记 stale，保留前面三步及人工选择；保存不执行模型或后续步骤，用户须重置 AI 阶段、单独运行 AI、审核并确认名单后重新预览导出。每次 AI 执行读取其开始时的保存规则快照，实际请求与缓存签名使用一致的提示词；正在运行的旧请求不会实时采用新保存的规则，不同规则的历史缓存不可冒充当前成功。

只有显式运行 / 继续 AI 才写新版投影并清除旧派生字段；打开历史任务不迁移。模型检查点只复用带 `simple-v1` 且两个字段有效、身份 / 签名一致的成功记录；旧 rich 即使 `status=success` 也失效并保留在历史记录，不计新版成功数。重跑保留人工取舍，只有“采用建议”重置。薪资与经验解析仍可留作独立标注，不参与新判断。

## 投递预览与 JSON 导出

投递页读取具名审核任务的前四步持久化状态，四步必须全部 `completed` 且 `confirmed=true`。只选取当前 AI 阶段 `keep_ids` 中的最终保留岗位；有效人工选择优先于先前 AI 建议，不把未确认、失效或已离开当前输入的历史决定当作授权。预览与导出不执行报告分类、语义重判、浏览器操作或模型请求。

预览返回 `source_task`、`summary`、`jobs`、`blocked_jobs` 与仅供本次发布核对的 `snapshot_token`。`summary` 使用 `selected_count`（最终保留）、`ready_count`（可导出）、`blocked_count`（阻断）三项，后两项之和等于前一项。目标缺少有效 BOSS ID / 详情链接、多个身份或来源链接互相冲突、复核记录无效时，岗位进入 `blocked_jobs`，不混入 `jobs`。人工选择保留不伪造模型成功记录，导出保留实际判断和状态。

文件根字段固定为 `schema_version="1.0"`、`export_id`、`generated_at`、`source_task`、`summary`、`jobs`、`blocked_jobs`。`snapshot_token` 属于内部预览接口，不作为下游业务字段。每层采用白名单，未知可选值用 `null`；不导出本机绝对路径、原始模型响应、凭据、Cookie、配置正文或日志。完整格式由 [delivery_jobs.v1.schema.json](../schemas/delivery_jobs.v1.schema.json) 定义，运行时使用标准库校验。

默认输出为 `<任务>/delivery-exports/<时间戳>-<uuid>/delivery_jobs.json`；指定 `--output-dir` 时，在该父目录中新建唯一子目录。临时内容完成校验后，在同一确认选择快照仍有效的前提下原子发布；变化或冲突会拒绝发布，须重新预览。新导出不覆盖既有文件，也不更改任务确认或取舍。历史快照不随任务改变而更新，JSON 不是已投递凭证；下游只读取 `jobs`，不自行将 `blocked_jobs` 当作可投记录。

导出及其缓存只读取任务内当前引用的安全阶段文件；阶段数据变化时重新捕获，不以旧缓存绕过状态、身份或路径校验。生成目录在任意深度均由 Git 忽略，也不纳入 wheel / sdist。读取示例见[命令行参考](command-line.md#投递-json-导出)。

## 显式兼容报告

旧五键 manifest、`process_architecture.py --stage report` 和旧工作台仍保留。默认三个模块不再提供第五步报告操作；历史报告不迁移、不改写，导出也不从 `hai_tou_pool.json` 反推当前名单。

兼容报告优先采用有效已确认的 AI 人工决定：人工保留进入“海投池”，人工剔除进入“暂不投”；没有人工决定时沿用 AI 默认三类，信息不足 / 失败 / 缺失进入“待核实”，不计入 `hai_tou_pool.json`。前置已确认剔除仍优先。报告只校验已有记录与当前输入，不读取模型配置或请求服务，不重新按关键词、职责证据或六维推翻 AI；JSON / Markdown 保留全量来源、原始判断、技术状态与最早剔除步骤。

报告返回集合仍须遵守当前确认输入，全量文件另追踪全部导入岗位。`review_selection` 保存生成时审计，人工摘要只展示前四步快照；生成后的旧文件不会因名单改变而自动更新。历史 rich 仅按兼容路径追溯，未签名或旧 rich 不能冒充新版成功。缺失、失效或身份 / JD / 提示词不匹配的记录默认待核实，当前有效已确认的人工决定仍保留实际技术问题。

## 模型访问、暂停与数据安全

AI 页面“AI 并发（每岗独立）”控制同时复核的岗位数。每个岗位单独提交完整规则和当前 JD，不跨岗位续接 `previous_response_id` 或重放历史；Responses 默认 `store=false`，Chat 只提交当前岗位消息。格式纠正与有限网络重试仍属于当前岗位。

每岗单独校验并保存检查点；普通继续跳过输入和配置仍有效的成功结果，只处理未完成岗位。恢复独立请求不删除已有结果，也不改变筛选规则、模型配置或人工名单。正在运行的旧进程不会热切换；暂停或停止并保存后，重启程序再继续本步即可使用独立请求。

检查点先写独立临时文件，再原子发布；Windows 上界面读取等短暂文件占用只作有界退避，不截断上一次完整文件。工作线程收到本岗检查点保存确认后才处理下一岗。保存或结果消费发生不可恢复异常时，处理器发布脱敏失败状态并停止后续岗位；桌面监控据此结束本次自有请求进程，阶段显示失败并保留已发布结果，不允许确认成已完成。排除故障后使用“继续本步”复用成功检查点；“重置本阶段”会清空当前阶段，不能用来恢复本次断点。

CLI 和 PowerShell 包装器也默认每岗独立（`--conversation-size 1` / `-ConversationSize 1`）；多岗会话参数仅保留为显式兼容选项，桌面始终传入 1。缓存签名仍代表当前岗位逻辑输入。详见[命令行参考](command-line.md)。

GUI AI 并发 `workers` 默认 10（1–32），与 JD 并发独立；模型初始默认 `gpt-5.6-luna`、思考强度 `max`。AI 页面“修改模型配置”可编辑服务地址、API 协议、模型、强度和 API Key；API Key 使用 Windows Credential Manager，不改全局 Codex 设置。API 协议默认“Responses API”，旧配置缺少 `api_mode` 时也按 Responses 处理；服务仅提供 Chat 接口时可选择“Chat Completions”。两种协议均可勾选“使用流式响应”，无需因流式要求切换协议。Chat 使用 `/chat/completions`、`messages`，不发送 Responses 的 `input`、`reasoning`、`store` 字段。Chat 强度可选，默认显示“未验证，不发送”；验证并保存后才发送顶层 `reasoning_effort`。CLI 使用项目配置，也可显式覆盖，见[命令行参考](command-line.md)。默认模型与强度统一定义于 `screening_policy.py`，实际请求与缓存提供方签名必须使用同一组配置。

流式请求使用 SSE；Responses 必须收到 `response.completed` 内的完整成功响应，再校验最终岗位 JSON。仅收到文本片段、正文结束事件或 `[DONE]`，以及失败、未完成或异常断流，均不算复核成功。Chat 继续要求完成片段和 `[DONE]`。分类名单在每个岗位完整校验并落盘后更新，不把逐字片段显示为最终判断。协议事件参考 [官方 Responses 流式文档](https://developers.openai.com/api/docs/guides/streaming-responses)。

配置窗口中先选协议、填入地址及密钥，可点“读取模型”查询 `/models`，也可手动输入模型名。两种协议共用模型列表接口；读取列表和普通连接成功都不启用思考强度。“测试连接”使用当前表单和有效参数发送短请求；未验证 Chat 输出上限 `max_tokens=16`，已验证 Chat 和“验证思考强度”使用 `1024` 给思考输出留空间。两种测试均不自动重试，可能产生少量用量。强度验证必须完整返回非空最终文本；HTTP 200、仅有思考内容、截断、错误或中断都不算成功。验证只确认参数被接受和响应完成，不能证明服务内部思考预算。修改地址、模型、强度、流式或密钥后需重新验证；验证期间改表单不能为新值授权。点“保存配置”后才生效，不运行复核或改写报告。[官方 Chat Completions 文档](https://developers.openai.com/api/docs/api-reference/chat/create)描述了消息和响应字段，具体服务的兼容范围仍以服务方支持为准。

CLI 与桌面按同一版本化签名复用成功模型记录：签名覆盖实际岗位输入、提示词与请求 schema、模型、服务地址、API 协议和实际生效的思考强度。本次两字段协议与 schema 使旧 rich 缓存失效；只有有效 `simple-v1` 才可复用。单独新增协议选项不改 Responses 的指纹规则；切换协议则使用另一组签名。未验证 Chat 不发送强度，验证后实际发送的强度参与签名。流式选项和验证摘要本身不属于语义输入，但改变流式选项会使强度验证失效，须再验证。密钥不进入缓存签名，服务地址仅保留摘要。输入或有效配置改变、缺少签名、旧 rich 或失败记录都不能冒充本次缓存成功。失效记录保留追踪，历史报告不自动改写。

凭据按单一来源解析：显式 API key 优先，其次所选 provider 的 `env_key`，再其次 `experimental_bearer_token`；没有 provider 专用凭据且需要 OpenAI 认证时，才读取本机 `auth.json` / `OPENAI_API_KEY`。显式配置的环境密钥缺失即报错，不轮试无关凭据。配置仅由显式 AI 执行使用，不写入任务偏好、日志、岗位结果或项目文件。

请求标识为 `boss-architecture-collector`，不伪装浏览器或桌面客户端。所有 API 重定向均拒绝且不重试，服务地址须使用最终端点，避免请求头或正文被带往另一地址；该规则同时适用于模型列表、连接与强度测试。HTTP 403 不重试或绕过，需向服务方确认授权；正式复核的超时、429 和 5xx 有限重试。错误只保留状态和处理提示，不回显响应正文、请求头或密钥。只有合法 JSON、字段齐全且非错误 / 未完成的结果才是成功复核。Chat 从首个 `choices[].message.content` 读取字符串或文本部分，兼容 Markdown JSON 代码块；空内容、错误、截断、过滤或工具调用结果均不能作为成功复核。

浏览器只在显式列表采集、JD 补抓或登录准备时使用，不复制普通浏览器 Cookie。遇验证保存检查点，等待人工完成后仅续本步，不确认或启动下步。暂停 / 停止会结束本次自有子进程树，未落盘岗位可能重抓。

审核页准备动作通过本项目 `browser_setup.py` 直接打开独立 Chrome / Edge 的 BOSS 窗口，成功表示窗口打开命令已发送且对应 CDP 可达；不读取或确认登录。JD 自动准备先复用可用登录态，否则打开专用窗口；登录或环境检查仍未通过时暂停，人工处理后继续本步。启动失败、CDP 未就绪与登录检查未通过分别报告，不能在窗口启动失败时只提示人工登录。浏览器 / profile 参数不传给不支持它们的上游命令行。

Windows 子进程挂起创建后加入自有 Job Object，再恢复对应初始线程，避免虚拟环境重定向器提前产生后代。父进程退出但后代占用输出时有界收尾；正常完成且排空输出的专用浏览器可保留。不按历史 PID 杀未知进程。强制终止无法执行 Python `finally`，既有 Chrome 可能遗留本次页面；初始 CDP 超时沿用上游，停止信号不保证瞬时打断。

源与任务路径拒绝符号链接 / 目录联接及路径逃逸。任务、阶段结果和 runtime 限定在本任务安全路径内，不得写入原始 `raw` / `prepared`；原子写及唯一目录防止覆盖旧任务。个人方案位于 `config/collection-plans/`，来源识别配置位于 `config/review-source-catalogs/`，二者与岗位数据默认不提交 Git。

源码态的上述默认路径位于项目内；安装态由 `project_resources.default_state_root()` 切换到用户状态目录，不向只读安装目录保存任务、采集结果、导出或个人方案。默认配置、提示词与导出 Schema 是发布资源，加载时检查清单与内容摘要；不从当前工作目录猜测替代资源。

## 关键接口契约

### 任务存储：`desktop_tasks.py`

```python
STAGES = ("import", "shortlist", "fetch-jd", "llm", "report")
# 存储兼容五键；默认桌面只展示和运行前四项。

ReviewTask.create(source_root: Path, task_parent: Path, name: str,
                  city: str | None = None, track: str = "all",
                  sample_size: int | None = None,
                  config_path: Path | None = None) -> ReviewTask
ReviewTask.open(path: Path) -> ReviewTask
ReviewTask.get_review_rules() -> str
ReviewTask.set_review_rules(rules: str | None) -> None
```

`job_id(job)` 优先 `job_id`，再 `dedupe_key / encrypt_job_id / job_link`；缺失或重复不能静默丢弃。状态错误使用 `TaskStateError(ValueError)`。

- `begin / finish / interrupt` 只负责本地存储与状态机，不运行浏览器、模型或子进程。`finish` 的建议：import / report 全部；shortlist 用 `list_pass`；JD 用明确 `recommended_keep`；LLM 仅接受明确 `True` / `False`，缺省 `None` 进入待核实。
- `set_keep / apply_recommendations / confirm` 服从上述审核约束，report 拒绝修改名单。`jobs(stage, include_excluded=True)` 返回本步全部结果；False 仅保留。输入 / 输出深复制，防止 UI 意外改写。
- `set_keep(stage, job_ids, keep, *, replace_selection=False, expected_stage=None)` 保留旧默认调用；`replace_selection=True` 仅允许 `keep=True`，一次事务将当前 `result_ids` 替换为给定 ID 保留、其余剔除，不清除暂时离开当前输入范围的历史人工选择。LLM 阶段待核实项同样支持逐岗、批量和完整替换人工选择；加载与刷新不能清除其 `manual_choices`。`expected_stage` 是已审核阶段快照，在同一文件锁内比较 `stage_selection_version` 后才写入；签名包含结果身份、输入 / 选择版本、确认状态及人工决定，不能只检查可能不变的 revision。
- `confirm(stage, *, expected_stage=None)` 保留旧调用兼容；GUI 必须传入已审核的快照，事务内用同一 `stage_selection_version` 核对后再冻结名单。冲突不写入任何确认结果。
- `all_jobs()` 合并导入基线与可用增强，保留全部来源和 `review_selection`，附 `excluded_at`（最早已确认剔除步骤或 null）。`run_directory(stage)` 只能定位本任务内 runtime。
- manifest 至少包含固定范围、配置身份、源清单及 `stages`；每步包含状态、确认、输入 / 保留 / 剔除 IDs、进度、统计、问题与版本引用。`snapshot / stage_info / record_progress` 提供持久化事实，不模拟数量。

### 执行适配：`review_pipeline.py`

```python
execute_stage(task: ReviewTask, stage: str, *,
              scraper_root: Path | None = None, workers: int = 10,
              batch_size: int = 30, jd_workers: int = 3,
              control: StageControl | None = None,
              on_event: Callable[[str, Any], None] | None = None) -> dict
prepare_browser(scraper_root: Path, on_event=None,
                control: StageControl | None = None) -> bool
```

同步执行，调用者放后台线程；执行器唯一负责 `begin / finish / interrupt`，UI 不重复调用。`StageControl.pause / stop` 保留检查点。回调仅发 `log`（脱敏文本）、`progress`（dict）、`waiting`（str）、`finished`（snapshot），不碰 Tk；界面通过队列在主线程读取落盘事实。`_report_markdown_lines(records, pool, metadata)` 可纯渲染已有结果，不重算分层或改任务。

### 方案、来源与 GUI 边界

- `collection_plan`：`validate_plan_config` 返回白名单深拷贝；`update_plan_config / select_plan_combinations / filter_plan_specs` 共享编辑与执行选择；`preview_rows` 只加中文展示字段；`save_plan_config` 唯一另存，拒绝联接，不覆盖旧配置。
- `collection_sources`：`assert_source_specs_compatible(root, specs)` 采集写前只读核对旧组合语义，缺失旧字段兼容；`review_config_for_source(source_root, fallback_config, output_dir=...)` 只在显式创建任务时合并来源 catalog，不过滤历史 raw。
- `CollectionPage(ttk.Frame)`：`on_use_source(Path)` 仅响应人工交接，`can_start()` 检查宿主空闲，`on_busy_change(bool)` 只在 Tk 主线程回调；`apply_theme` 不执行任务，`request_close` 非阻塞停止并清理自有回调。`shutdown_complete` 表示后台线程和自有子进程均已退出。
- `ReviewDesktopApp(root, args, *, executor=execute_stage, browser_preparer=prepare_browser, collector_opener=None)` 支持离线注入。大文件读取、创建任务和外部执行放后台；主线程更新控件。关闭宿主后不再发起刷新，等待自有后台工作收尾。系统文件选择器和消息框可能仍随 Windows 主题。

状态机、确认输入、人工选择、stale、路径保护、JD 完整度、验证中断、子进程归属和 UI 事件应使用临时数据 / 伪进程验证；命令与当前检查记录统一见[开发文档](development.md)。离线测试、布局几何或历史清单读取不等同于真实网站采集、模型服务授权、并发稳定性或桌面截图视觉验收。
