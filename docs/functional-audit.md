## 验证与使用边界

使用临时合成任务、替身进程及透明禁用的真实 Tk 窗口验收。覆盖连续中断与保存失败窗口、非零退出、完整 catalog 与 Windows samefile、公司字段和无效源提示、JD 分片 / 批次 / 隔离、配置竞态与私有 stdin、实时签名、导出身份与历史快照、小窗口 / 高 DPI 及共享 UI 生命周期。

关键新增验收见 [采集修复测试](../tests/test_collection_audit_fixes.py)、[审核后端修复测试](../tests/test_review_backend_audit.py)、[桌面修复测试](../tests/test_desktop_audit_fixes.py)，其余模块回归与构建安装沿用[开发文档](development.md)的入口。独立复核没有将实现测试通过等同于真实外部服务验证。

最终集成补验：最新导出空值裁剪、字段选择及中文文件名与上述修复共同验收，后端定向 40 项、真实 Tk 定向 11 项均通过；临时 wheel 的资源白名单、安装态合成任务导出，以及缺失 / 无效资源拒绝构建共 3 项通过。此为本次集成的定向补验，不代表再次运行整个项目测试集。

自动化回归使用合成数据；按用户要求另对现有任务作本地只读核对并生成新导出，未连接 BOSS 或模型、未读取个人浏览器状态或凭据。已有运行进程不会热加载代码，安全暂停后重开程序才能使用新版。旧检查点已经丢失的第二来源无法凭空补回，需从原始来源重新导入；历史任务、报告和导出不自动迁移，不清除有效成功缓存或人工选择。

### 发布前修正（2026-11-01）

- Windows 检查点路径比较统一等价的普通 DOS / UNC 与扩展长度前缀，避免原子替换期间误报越界；仍校验词法和解析后的双重边界，拒绝设备路径、真实逃逸、符号链接和目录联接。无法可靠解析时停止访问，暂时访问错误只作短时有界重试，不再伪装成越界。执行器、任务存储、清理和界面定位使用同一比较规则。
- 双浏览器 JD 续跑按完整批次的固定分片识别实际仍有待抓岗位的一侧；仅剩 Edge 岗位时正常准备 Edge，已完整缓存的空侧不要求重新登录。岗位归属、输入顺序、合并和人工验证边界不变。
- 去重保留各来源的白名单公司名称候选及来源信息，导入公司排除词检查全部候选；招聘者姓名不当作公司名称，已有主公司字段的优先级不变。

新增确定性与临时目录回归见 [Windows 路径](../tests/test_checkpoint_paths.py)、[流水线路径保护](../tests/test_review_pipeline.py)、[双浏览器续跑](../tests/test_dual_browser_jd.py) 和 [公司来源候选](../tests/test_import_company_candidates.py)。缓存性能验收使用带当前输入双签名的真实有效夹具，不放宽生产校验。已有运行进程不会热更新；本次修正不清理或重置真实任务。
