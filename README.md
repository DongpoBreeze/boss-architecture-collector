# BOSS 架构岗位采集器

Windows 岗位采集、人工审核与 JSON 导出工具。默认桌面程序在同一窗口提供“01 岗位采集”“02 后处理审核”“03 投递数据导出”：采集列表，在四步审核中逐步确认名单，再把最终保留岗位导出为稳定 JSON，交给独立的后续工具读取。

本项目不自动投递、不联系招聘方、不绕过验证码或安全验证。采集通过上游 [boss-zhipin-scraper](https://github.com/eatmoreduck/boss-zhipin-scraper) 的 Chrome DevTools Protocol（CDP）接口执行。

## 启动

推荐 Python 3.11+，最低 3.10，并包含 Tcl/Tk（`tkinter`）。本地审核和导出使用标准库；Python 3.10 读取 AI 的 TOML 配置需安装条件依赖 `tomli`。实际采集、JD 补抓还需上游工具及其依赖，AI 复核使用本机保存的模型配置。

在项目目录双击 `run_desktop.bat`，或运行：

```powershell
.\run_desktop.bat

# 可选：预填采集源和上游安装位置
.\run_desktop.ps1 -Root "D:\岗位数据\采集源" -ScraperRoot "D:\工具\boss-zhipin-scraper"
```

启动器优先使用项目虚拟环境，再检查已激活环境和系统 Python；可用 `-Python` 指定解释器。它不安装包、不修改全局配置。前台排查可用 `python desktop_app.py`，完整参数见[命令行参考](docs/command-line.md)。

默认进入“02 后处理审核”。启动、切页、打开任务、选择步骤、确认名单和导出预览均不采集、不请求模型。三个页面保留各自状态，共享主题与执行互斥；F5 只刷新当前页。

## 01 岗位采集

选择输出根、上游目录和检索条件，预览并勾选组合，再点击“开始 / 续采”。采集只保存原始列表、日志、清单和实际方案快照。完成后手动点击“用此数据新建后处理任务”仅填入表单，仍需自己创建、运行及确认任务。

“采集浏览器”默认由 Chrome 和 Edge 同时执行，也可选“仅 Chrome”；两侧使用独立 CDP 端口（9222 / 9223）及 profile。先按当前勾选和数量上限确定执行组合，再分给两侧，结果保存在同一个输出根。页面分别显示两侧状态与当前位置，日志带浏览器名称，汇总进度以落盘清单为准。“准备浏览器 / 登录”准备所选浏览器，需要分别完成 BOSS 登录；一侧等待验证时，另一侧继续采集。验证后点击该侧“人工完成，继续”；暂停、停止和关窗会保存两侧进度，重新开始跳过已完成组合。

“每浏览器采集并发”可设为 1–8，默认 3；双浏览器各开最多 3 个独立采集页面，合计最多 6 个，实际不超过分配的组合数。每个浏览器只准备登录一次，槽位详情可在“浏览器槽位”中查看。“翻页等待”默认最短 12 秒、最长 22 秒，可设置 0–300 秒的小数范围；两者相同时为固定等待，只改变列表两页之间的间隔。运行中设置锁定，暂停后可调整再续采。

并发时某侧遇到验证，会停止该侧继续开始新组合。人工完成后点击对应继续按钮，只重试当前等待的组合；其余组合在本轮结束后通过“开始 / 续采”补齐，另一浏览器继续保存进度。

默认 [检索方案](config/architecture_collection.json) 为 6 城（上海、深圳、杭州、广州、成都、北京）、2 档薪资、本科；当前求职 11 个关键词 × 4 个经验段，成长参考 6 个关键词 × 2 个经验段，共 672 组，每城 112 组。检索分组是查询条件。每组 1–10 页不增加组合数；“本次最多检索”按预览顺序取前 N 个所选组合，留空表示全部，已完成组合仍会跳过。

“编辑检索条件…”和“加载方案…”可调整查询；保存会另建方案。已有完整数据可直接进入后处理。

## 02 后处理审核

1. 选择包含 `raw/current`、`raw/target` 的完整采集根；不要选择 `raw`、`prepared`、旧运行或具名任务目录。
2. 填任务名、城市、检索轨道和去重岗位数量，点击“创建任务”。默认不限，自定义数量为正整数，超出可用量时取实际数量。创建只建立本地任务。
3. 每一步单独点击“运行本步”，查看原文、来源与依据，按需保留、剔除或“采用建议”。
4. 确认本步名单后，下一步仍需手动运行。最后确认 AI 名单，再去“03 投递数据导出”预览和导出。
5. 下次打开同一个具名任务目录，可继续原范围、人工选择和检查点。

| 步骤 | 作用 | 外部访问 |
| --- | --- | --- |
| 1. 导入与去重 | 合并来源，按去重岗位数均衡选择 | 无 |
| 2. 列表初筛 | 本地宽筛，展示薪资、经验及方向依据 | 无 |
| 3. JD 补抓 | 仅补正文和完整度，不作职责筛选 | BOSS 详情 |
| 4. AI 语义复核 | 完整 JD 进入模型；建议符合保留、不符合剔除，其余待核实 | 本机配置的模型服务 |

列表初筛分“明确相关 / 待核实 / 剔除”三队列，默认保留前两类；分数只排序。明确月薪上限低于 17K 建议剔除，多来源时只有全部候选都能确定上限且均低于 17K 才触发。来源字段冲突保留候选与出处；未知信息不猜测。队列操作仍须人工确认，规则见[工作流契约](docs/desktop-review-workflow.md)。

四步均可通过“修改本步规则”查看并编辑当前任务规则：导入使用字段要求与排除词，初筛使用方向开关和词表，JD 使用滚动次数、速度档位与每页额外等待范围，AI 保留文字规则。保存不执行任务；实际修改使本步和后续旧结果失效，人工选择与原始数据保留。初筛不再显示无作用的“执行设置”。

三页共同动作、分页、搜索和规则弹窗使用统一控件；“全选本页”只选中，明确点击“保留所选 / 剔除所选”才改名单。六步骤功能缺口、冗余及修复状态见[功能检查清单](docs/functional-audit.md)。

初筛运行中分批更新已落盘的保留、剔除与待处理名单，AI 运行中自动更新保留、剔除、待核实名单。未处理项不冒充剔除，部分结果不能确认成完成。结果有效且 AI 未运行时，待核实项也可逐条或批量人工保留 / 剔除。人工决定在刷新、重开和普通续跑后保留，点击“采用建议”才清除覆盖；确认后的有效人工决定优先于 AI 建议。确认会核对实际看到的名单版本，多窗口冲突须刷新后重新审核。

AI 目标为企业 AI 解决方案架构师 / AI 应用架构师、AI 产品经理，以及能积累业务需求分析、方案设计、集成、PoC、交付与迭代经验的相关岗位。模型只返回 `{"判断":"符合|不符合|信息不足","理由":"一两句话"}`，本地追加身份、状态与缓存签名。原始 AI 判断和技术状态会保留，人工选择不补发模型请求。

JD 每个浏览器页面并发默认 3、AI 每岗独立请求并发默认 10，均可设为 1–32；GUI 批大小默认 30。桌面新设置默认 Chrome + Edge 各半，已有单浏览器偏好保留；两侧各使用页面并发值与独立端口 / profile。一侧遇验证会保存另一侧已完成的 JD，续跑只补未完成项。

在“JD 补抓 → 修改本步规则”设置“每页等待最短 / 最长秒数”，均为 0–30 的整数，最短不能大于最长；默认 0 / 0，不额外等待。保存到本任务后，下次运行或续跑时每个 JD 页面打开前在范围内随机等待；相同值表示固定等待。页面上显示当前范围，等待中支持暂停或停止，原有渲染与滚动等待仍保留，已补齐的 JD 继续复用。

AI 初始默认 `gpt-5.6-luna` / `max`、Responses API。可在 AI 页修改服务、协议、模型、强度和流式选项；API Key 只存 Windows Credential Manager。Chat Completions 的思考强度须单独验证并保存后才发送。保存配置不运行 AI，更换有效请求配置须显式重跑。规则修改也只影响本任务；“恢复默认”先改草稿，保存后须重置、运行 AI、审核并重新确认名单。更多模型与缓存约定见[工作流契约](docs/desktop-review-workflow.md)。

BBLabu 的 Claude 可使用现有 Chat Completions 兼容模式：服务地址填 `https://api.bblabu.ai/v1`（包含 `/v1`），模型选择服务“读取模型”返回的准确 ID。本次验证的 ID 为 `claude-opus-5-5`，不是简写 `claudeopus5.5`；普通与流式连接及两字段岗位复核均通过。推荐先关闭流式、不发送未验证的思考强度，不套用 GPT 的 `max / xhigh`。这只表示该服务接受相应请求，模型列表和授权以服务当前返回为准；不改全局 Codex 配置、项目发布默认值或历史结果。

## 03 投递数据导出

选择已完成并确认前四步的具名任务。预览只读取当前任务结果，显示最终保留数、可导出数和阻断数；只从 AI 阶段最终确认的保留名单取岗位。未确认、失败、运行中或失效的前置阶段不能导出。

导出按最终确认的保留名单执行，不再次验证 AI 记录、判断或缓存签名；已有判断、理由与运行状态仅作记录，标记 `validation="not_checked"`，AI 失败、缺失或旧记录不阻止已保留岗位导出。真实 BOSS 岗位 ID 或有效详情链接供下游定位目标；缺失、格式错误、互相冲突或重复的目标仍进入 `blocked_jobs` 并保留原因。导出采用字段白名单，不带原始模型响应、凭据、Cookie、日志或本机路径。

公司名称使用 `company` 字段，01 新采集独立保存并传递至导出。旧 API 数据中存入 `boss_name` 的公司名称可直接恢复；在 03 刷新预览后选择“公司”或导出完整 JSON，无需重跑 AI。公司 ID、链接、行业、规模和融资阶段也支持导出。

招聘经验使用 `experience` 字段，03 中显示为“经验要求”。01 从岗位 API 的经验字段或页面的明确经验标签采集；旧数据可从 `1-3年 | 本科`、`经验不限 | 本科`、`在校/应届 | 本科` 等标签恢复。刷新 03 即可导出，无需重跑审核；检索时选择的经验筛选不充当岗位要求。

“选择导出字段…”根据当前 02 已确认数据生成选项：某字段只要在对应岗位列表中至少一条记录有值就可选；当前不存在或全部为空的字段不添加，没有阻止项时也不显示阻止导出岗位组。支持逐项选择嵌套字段、搜索、全选、清空和按父级批量选择，至少勾选一项。首次全选，刷新或切换任务后仅保留仍有值的已选字段；若原选择全部消失，自动选用当前可用字段。取消编辑保留原选择。“导出指定信息”保存勾选字段及必要层级；“导出完整 JSON”独立保存全部有值的支持字段。

字段目录、岗位详情和两种导出均省略 `null`、空白文本、空数组和空对象，保留有效的 `0`、`false` 与非空文本；清理后没有内容的父对象或岗位占位也省略。格式版本、导出 ID 和导出时间是生成的导出信息，仍可选择。

文件名按字段列表顺序，取前三个已选且有值字段的中文名，用下划线连接；不足三项就用实际项数，超过三项也只取前三项。例如 `岗位名称_公司_薪资.json`，没有值的城市字段不参与命名。页面实时显示预计文件名；完整 JSON 使用全部可用字段顺序，命名为 `格式版本_导出ID_导出时间.json`。每次导出仍在选定父目录下新建唯一目录：

```text
<任务目录>/delivery-exports/<时间戳>-<uuid>/<前三个字段中文名>.json
```

每次导出保留独立快照，发布前重新核对所预览的确认名单；名单变化时拒绝发布，须重新预览。导出不重新分析报告、不调用浏览器或模型，也不改变任务名单。导出的 JSON 表示当时的审核结果，不表示岗位已经投递。

完整 JSON 根包含 `schema_version="1.0"`、`export_id`、`generated_at`、`source_task`、`summary`，有记录时才包含 `jobs` / `blocked_jobs`；指定信息导出可省略任意未选字段。例如只选 `jobs.title` 和 `jobs.company`，有值时文件只包含 `{"jobs":[{"title":"…","company":"…"}]}`。完整格式的稳定字段及读取示例见[命令行参考](docs/command-line.md#投递-json-导出)，Schema 为 [schemas/delivery_jobs.v1.schema.json](schemas/delivery_jobs.v1.schema.json)。

## 数据与续跑

```text
采集源/
  collection_manifest.json
  raw/current/、raw/target/        原始列表与日志
  collection-plans/               GUI 实际使用的方案快照

job-result/review-tasks/task-…/    默认任务位置，可另选父目录
  task_manifest.json              固定范围、阶段状态与人工选择
  raw_sample.json、task.log
  stages/                         版本化结果
  runtime/                        本任务的 JD / 模型检查点
  delivery-exports/
    <时间戳>-<uuid>/<前三个字段中文名>.json
```

原始数据只读，任务使用唯一目录，不得放进 `raw` / `prepared`。创建后数据源、城市、轨道、数量与配置固定；换范围或补采后应新建任务。个人方案与来源识别配置可能被任务固定引用，不能当缓存随意删除。

暂停、停止和人工验证保留已落盘检查点。回改已确认名单、重跑或重置上游会使受影响下游失效；旧文件保留追溯，重跑并确认后才可再次导出。旧导出快照保留其原始内容。确认空名单合法，后续空 JD / AI 不启动浏览器或模型。

默认桌面已不运行“生成报告”。任务清单内部仍保留旧五键结构以便兼容；历史报告不迁移、不改写。显式兼容 CLI 的报告和旧工作台仍可使用，CLI 运行目录不能当作新审核任务。

## 安装与文档

在包含 Tcl/Tk 的虚拟环境中也可安装：

```powershell
python -m pip install .
boss-architecture-desktop
boss-architecture-collect --dry-run
boss-architecture-export --help
```

源码默认路径保持不变。安装后，默认配置、提示词和导出 Schema 为包内只读资源；默认任务、采集结果和个人方案写入 `%LOCALAPPDATA%\boss-architecture-collector\`，缺失时回退 `~/.boss-architecture-collector`。已有数据由用户选择，不复制、不迁移。发布包仅包含白名单源码与静态资源，岗位、导出快照、个人配置和凭据不纳入 Git 或发行包。
