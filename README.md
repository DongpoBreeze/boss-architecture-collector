# BOSS 架构岗位采集器

Windows 岗位采集与人工审核工具。默认桌面程序在同一窗口提供“01 岗位采集”和“02 后处理审核”：前者只采集列表，后者围绕固定数据源、具名任务完成五步审核。采集通过上游 [boss-zhipin-scraper](https://github.com/eatmoreduck/boss-zhipin-scraper) 的 Chrome DevTools Protocol（CDP）接口执行。

本项目不自动投递、不联系招聘方、不绕过验证码或安全验证。请遵守 BOSS 直聘用户协议、当地法律及上游项目的合规说明。

## 启动桌面程序

推荐 Python 3.11+，最低 3.10，并包含 Tcl/Tk（`tkinter`）。GUI 和本地文件审核不需要额外依赖；Python 3.10 读取 AI 的 TOML 配置需另装 `tomli`（3.11+ 自带 `tomllib`）。实际采集、JD 补抓还需安装上游工具及其依赖，AI 步骤使用本机配置的模型服务。

从源码使用时，在项目目录双击 `run_desktop.bat`，或在 PowerShell 中运行：

```powershell
.\run_desktop.bat

# 可选：指定已有采集源和上游安装位置，路径按实际环境替换
.\run_desktop.ps1 -Root "D:\岗位数据\采集源" -ScraperRoot "D:\工具\boss-zhipin-scraper"
```

启动器优先使用项目虚拟环境，再检查已激活环境和系统 Python；可用 `-Python` 显式指定解释器。它不安装包、不修改全局配置。启动失败时，可用 `python desktop_app.py` 前台排查。完整参数见[命令行参考](docs/command-line.md)。

默认进入“02 后处理审核”。启动、切页、打开任务、选择步骤和确认名单均不会自动采集或请求模型；两个页面保留各自状态，执行互斥，F5 只刷新当前页面。

### 可选：隔离安装

也可在包含 Tcl/Tk 的 Python 虚拟环境中安装；这不会打包成单文件 EXE：

```powershell
python -m pip install .
boss-architecture-desktop

# 只读检查，不采集或调用模型
boss-architecture-collect --dry-run
boss-architecture-process --help
```

源码启动的默认位置保持不变。安装后，配置和提示词是包内只读资源，默认任务、采集结果和个人方案写入 `%LOCALAPPDATA%\boss-architecture-collector\`；没有 `LOCALAPPDATA` 时回退到用户目录 `.boss-architecture-collector`。已有采集源仍由你选择，不复制、不迁移。发布资源只包含默认检索配置和提示词，不包含个人方案、岗位数据或凭据。构建及离线安装边界见[开发文档](docs/development.md)。

## 采集新数据

在“01 岗位采集”选择输出根、上游目录和检索条件，预览并勾选本次组合，再点击“开始 / 续采”。

默认方案位于 [config/architecture_collection.json](config/architecture_collection.json)：5 城、2 档薪资、本科，当前求职 11 个关键词 / 4 个经验段，成长参考 6 个关键词 / 2 个经验段，共 560 组，上海 112 组。“检索分组”是检索条件，不是最终投递分层；一个组合是一套完整查询，每组 1–10 页不增加组合数。

“编辑检索条件…”和“加载方案…”支持调整条件；保存时另建方案，不覆盖默认配置。逐组勾选后，“本次最多检索”按预览顺序取前 N 组，留空表示全部；它不是岗位数，也不是新增 N 组，已完成组合仍会跳过。

采集只写原始列表、日志、清单和实际方案快照，不运行后处理。完成后可手动点击“用此数据新建后处理任务”，仅填入新任务表单，仍需自己创建、运行及确认。若已有完整采集数据，直接使用后处理页即可。

## 审核已有岗位

1. 选择包含 `raw/current`、`raw/target` 的完整采集根，不选 `raw`、`prepared`、旧运行或具名任务目录；文件夹日期不影响处理。
2. 填任务名、城市、检索轨道和去重岗位数量，点击“创建任务”。默认全部岗位（不限）；自定义为正整数，超出可用量时取实际数量。创建仅建立本地任务。
3. 对每一步分别点击“运行本步”，查看岗位原文、全部来源与依据，按需剔除、恢复或“采用建议”。
4. 点击“确认 N 个进入下一步”冻结名单。确认不运行下一步，下一步仍须手动启动。
5. 下次点击“打开任务”，选择原具名任务目录，继续原范围、人工选择与检查点。

| 步骤 | 作用 | 外部访问 |
| --- | --- | --- |
| 1. 导入与去重 | 合并来源，按去重岗位数均衡选择 | 无 |
| 2. 列表初筛 | 本地宽筛，展示薪资、经验及方向依据 | 无 |
| 3. JD 补抓 | 仅补正文和完整度，不作职责筛选 | BOSS 详情 |
| 4. AI 语义复核 | 仅完整 JD 送入模型；符合建议保留，不符合建议剔除；未完成或信息不足进入待核实，不进入保留/剔除名单 | 本机配置的模型服务 |
| 5. 生成报告 | 追踪全部导入岗位，输出三层报告和可投池 | 无 |

AI 运行中会自动读取新落盘的判断，更新保留、剔除、待核实名单与数量，无需手动刷新。搜索与名单分组在后台处理，表格只更新当前页发生变化的行，保留当前选择与滚动位置。信息不足及未完成项保持独立待核实，不计入可投池。多窗口同时改名单时，确认会核对你实际看到的版本；发生冲突需刷新后重新审核。

列表初筛把岗位分成“明确相关 / 待核实 / 剔除”三个方向队列，分数只排序、不设最低分。默认建议保留前两类；可用队列筛选查看依据，再点“仅保留明确相关”或“加入待核实”调整本次名单。它们仍须人工确认后才能进入 JD 补抓，不代表已经满足投递要求。重新初筛保留既有人工选择；需要按新规则恢复默认名单时，点“采用建议”。

打开没有新队列字段的旧任务时，界面显示“旧版兼容”，不会按新规则自动重判。需手动重跑列表初筛，队列快捷动作才可用；原有逐岗取舍不受影响。

明确月薪上限低于 17K 的岗位仍建议剔除；同一岗位有多来源薪资时，只有全部候选均为明确月薪上限且都低于 17K 才触发该门槛。上限等于 17K、跨 17K 或未知上限不因该门槛剔除。来源字段冲突保留候选与出处并提示核实，避免初筛受来源读取顺序影响。强相关架构 / 产品标题不因缺少技能标签漏召回；销售的 AI 产品名词、开发的“架构设计经验”不当作本人方案职责。详细排除、证据及最终分层约定见[工作流与规则](docs/desktop-review-workflow.md)。

JD 每个浏览器页面并发默认 3、AI 请求并发默认 10，均可设为 1–32，彼此独立；GUI 每批默认 30，用于检查点分组，不是并发数。桌面 JD 页直接展示浏览器模式、登录准备按钮及两侧状态，新设置默认“Chrome + Edge 各半”；已有明确保存的单浏览器选择仍保留，可在本页切换并立即保存。CLI 继续默认单 Chrome，可用 `--browser-mode dual` 切换。双侧并发各为页面并发值，例如设为 2 时最多同时打开 4 个页面；本批只剩 1 个岗位时仅分给 Chrome。Chrome 和 Edge 分别默认使用 CDP 9222 / 9223 及独立 profile，岗位稳定均衡分成前后两个连续分片。两侧结果先分别写入检查点，再按输入顺序合并；一侧验证暂停时保留另一侧已完成结果，续跑仅重试未完成的岗位。两个实例不得共用端口或 profile。

AI 语义复核初始默认使用 `gpt-5.6-luna`、思考强度 `max` 和 Responses API；旧配置未保存协议时仍使用 Responses。在“AI 语义复核”页点击“修改模型配置”，可修改服务地址、API 协议、模型、思考强度和 API Key。服务仅兼容 Chat 接口时选择“Chat Completions”，使用 `/chat/completions`；如服务要求流式请求，勾选“Chat 使用流式响应”。Chat 默认不发送强度，点击“验证思考强度”，模型完整返回后再保存，才会发送顶层 `reasoning_effort`。修改地址、模型、强度、流式或密钥后须重新验证。API Key 仅存于 Windows Credential Manager，不写入源码、日志、岗位结果或全局 Codex 配置。

可先“读取模型”或手动填写模型名，再点“测试连接”；读取列表和普通连接成功不代表强度已验证。“验证思考强度”单独发送一次短请求，不自动重试；HTTP 200、空文本或截断结果均不能作为验证成功。成功仅说明服务接受参数并完整返回，不能证明内部思考预算。点击“保存配置”后才用于后续 AI 复核，保存不运行 AI。CLI 使用同一项目配置，也可用 `--base-url`、`--api-key`、`--model`、`--reasoning-effort` 和 `--api-mode responses|chat_completions` 覆盖本次请求。更换有效请求配置后，需重跑 AI；Chat 只有已验证且实际发送的强度参与缓存签名。默认 Responses 保留原有签名，升级不会仅因新增协议选项使已有成功缓存失效；历史报告不会自动改写。

AI 接收完整职位职责与任职要求，目标为企业 AI 解决方案架构师 / AI 应用架构师、AI 产品经理（应用 / Agent / 知识库），以及能积累业务需求分析、方案设计、系统集成、PoC、交付与迭代经验的相关岗位，不强求同名。排除主业代码开发、算法研究 / 模型训练、硬件、纯销售 / 渠道招商、底层基础设施；仅需懂技术或配合开发的产品、方案岗位不能误判为纯开发。

模型严格只返回 `{"判断":"符合|不符合|信息不足","理由":"一两句话"}`，岗位 ID、模型、状态及缓存签名由本地程序追加，格式标记为 `simple-v1`。AI 页只展示判断、理由及必要运行 / 技术信息；符合建议保留，不符合建议剔除，信息不足或未完成进入独立待核实队列，不能人工放入保留/剔除名单。新版报告直接按同一判断进入海投池 / 暂不投 / 待核实；待核实岗位保留全量追踪但不进入可投池，不再用关键词、证据门槛或六维推翻结论；人工确认剔除优先，列表初筛仍保留原有独立规则。

在 AI 页点击“修改复核规则”可编辑当前任务。旧自定义规则不会因打开任务而静默替换；采用新默认的准确操作是：**修改复核规则 → 恢复默认 → 保存本任务规则 → 重置 AI 阶段 → 单独运行 AI → 审核并确认名单 → 生成报告**。恢复默认只改编辑框草稿，必须保存；保存不请求模型，保留已抓 JD、来源及人工选择，受影响的 AI / 报告标记待重跑。重置只清空 AI 阶段文件和进度，不会立即运行；AI 重置后单独点击“运行本步”时，旧版复杂规则才会切换为简化默认。旧 rich 结果只读追溯，不能作为新版成功缓存复用；重新运行时失效结果保留历史。

前四步可改名单，报告页只读。报告生成完成后即可点“打开报告”，无需先确认报告完成；确认报告只更新任务状态，不重写输出。

## 数据与续跑边界

采集源与审核任务是两种目录，不可互换：

```text
采集源/
  collection_manifest.json
  raw/current/、raw/target/       原始列表与日志
  collection-plans/              GUI 实际使用的方案快照

job-result/review-tasks/task-…/   默认具名任务位置，可另选保存父目录
  task_manifest.json            固定范围、五步状态与人工选择
  raw_sample.json、task.log
  stages/                       版本化输入与结果
  runtime/                      本任务自己的 JD / 模型检查点
  runtime/shortlist/prepared/jd_shortlists/
    jd_input.json               明确相关 + 待核实的建议合并名单
    jd_relevant.json            明确相关方向队列
    jd_verify.json              待核实方向队列
  runtime/report/prepared/
    merged_jobs_index.json      全部导入岗位及剔除审计
    hai_tou_pool.json           可投岗位，不含已确认剔除项
    海投分层清单.md
```

原始数据只读，具名任务使用唯一目录；任务不能放进 `raw` / `prepared`。任务创建后数据源、城市、轨道、数量与配置固定，换范围或对源补采后应新建任务。来源方案的新关键词会在新建任务时合并识别，不因后来取消检索勾选而丢掉历史 raw。

列表步骤的三个 `jd_*.json` 是本轮规则建议；实际 JD 补抓只读取任务中人工确认的名单，可能与建议文件不同。队列及其数量随初筛结果保存，不因界面筛选而重新判定。

暂停、停止和人工验证保留已落盘检查点；处理登录 / 验证后继续当前步骤，未落盘岗位可能需要重抓。回改已确认名单或重跑上游会使已执行下游变为“待更新（stale）”；旧文件保留追溯，但须重跑及确认后才能作为新结果使用。人工选择在重跑中保留，只有“采用建议”才重置。

允许确认空名单；后续空 JD / AI 步骤只写本地检查点，不启动浏览器或模型，报告仍保留全部导入岗位的去向。完整的固定源、状态机、安全限制与已知边界见[工作流契约](docs/desktop-review-workflow.md)。
